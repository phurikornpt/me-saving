## ที่มีอยู่แล้ว (ต่อยอด ไม่ทำซ้ำ)
- เปลี่ยนหน้าแบบสไลด์ด้วย View Transitions (`globals.css`, `src/client/nav.ts`)

- ตัวเลขนับขึ้นลง (`AnimatedNumber.tsx`) ใช้ในวิดเจ็ตคนและกระเป๋าเงิน · แถบ XP เติมแบบ transition
- รายการล่าสุดเข้า/ออก (`RecentWidget.tsx`) · pill กระเป๋าเงินเลื่อนตาม (`layoutId`)
- +XP, ฉลองเลเวลอัป/streak 7-30-100 (`Feedback.tsx`) · toast
- วงล้อเด้ง (`ModeWheel.tsx`) · ก้อนเมฆ Aurora (`AuroraCloud.tsx`)
- สั่นเมื่อผิดพลาด: ช่องจำนวนเงินตอนกดเลขไม่ได้ (`NewEntryScreen.tsx`), ปุ่มลัดตอนล้มเหลว (`PresetChip.tsx`)
- ตอน AI อ่านรูป (`Loading.tsx` `ReadingReceipt`): ไอคอนใบเสร็จ + เส้นสแกน + ข้อความที่เปลี่ยนทุก 3 วินาทีตามเวลา **ไม่ผูกกับสถานะจริง**

## หลักการ
1. **Aurora = AI กำลังทำงาน** ใช้เป็นสัญลักษณ์เดียวกันทุกจุดที่เรียก AI ผู้ใช้จะเรียนรู้ว่าเห็นแสงนี้คือใช้โควตา
2. **ห้ามทำให้การจดช้าลง** แป้นตัวเลข ปุ่มลัด และการกดบันทึกคือหัวใจ (FR-1) animation ตรงนั้นไม่เกิน ~150 ms และห้ามบังการกด
3. **ความคืบหน้าต้องเป็นของจริง** ขั้นที่วัดได้ (ย่อรูป, ได้ผลแล้ว) แสดงตามจริง ขั้นที่รอ AI อย่างเดียวห้ามแต่งเปอร์เซ็นต์
4. ขยับเฉพาะ `transform` / `opacity` · หยุดเมื่อซ่อนแท็บ · มี Aurora ทีละตัว · เคารพ reduce motion ทุกจุด

## พื้นฐานที่ทำก่อน
- **`src/client/motion.ts`** เก็บความยาวมาตรฐาน (เร็ว 150 / ปกติ 250 / ช้า 400 ms) และ spring ที่ใช้ซ้ำ ตอนนี้ค่ากระจายตามไฟล์ (เช่น spring `420/26` ในวงล้อ)
- **`AuroraCloud` ปรับขนาดได้ และมีสถานะ `error`** (หมดสีเป็นเทาแล้วนิ่ง) เพื่อใช้ซ้ำในข้อ 1, 4, 6
- **สวิตช์ "ลดการเคลื่อนไหว" ใน ตั้งค่า > หน้าตา** ตอนนี้เคารพแค่การตั้งค่าของระบบ ถ้า motion เยอะขึ้นควรปิดในแอปได้เอง (ช่วยประหยัดแบตตอน Aurora ทำงานด้วย)
- **Haptic เป็นชุดเดียว** สั่นแค่ 3 จังหวะ: บันทึกสำเร็จ, streak ติด, error · ข้อจำกัด: `navigator.vibrate` ใช้ได้เฉพาะ Android, iPhone ไม่สั่น

## แผนลงมือ

### กติกาทั่วไป
- **1 milestone = 1 PR** ไปที่ `develop` เรียงตามลำดับ M1 → M4 แต่ละ PR ต้องผ่าน `pnpm eslint src`, `pnpm vitest run`, `pnpm build` และไม่เพิ่ม error ของ `tsc`
- **ส่วนที่ตัดสินใจเองได้ต้องมี unit test** (ฟังก์ชันล้วน เช่น ตัวคำนวณ delay ของการไหลเข้า, ตัวแยกประโยค, store ของค่าลดการเคลื่อนไหว, flag "เพิ่งจด") ส่วนหน้าตา animation ตรวจด้วย Vercel preview บนมือถือจริงก่อน merge
- **ทุก animation ใหม่ต้องผ่านตัวตัดสินเดียว** ว่าลดการเคลื่อนไหวหรือไม่ (ดู M2 "สวิตช์") จนกว่า M2 จะเสร็จ ให้ใช้ `useReducedMotion()` ของ motion และ `@media (prefers-reduced-motion)` ไปก่อน
- ไม่แตะเส้นทางแป้นตัวเลขของหน้าจดเร็ว นอกจากที่ระบุ

### M1 · PR 1 — รอ AI + สองจุดที่เห็นทุกวัน (เขียนแล้ว)

ที่ต่างจากแผนเดิมเล็กน้อย: ไม่ได้เพิ่ม prop `done`/`error` เฉยๆ แต่ย้ายค่าของแต่ละโหมดเป็นตาราง `CLOUD_LOOK` ที่ export และมีเทสต์ · ข้อความช้าใช้ hook `useSlowAfter` ใน `Loading.tsx` · ปุ่มย้อนกลับใน toast ซ่อนแถบนับเวลาเมื่อลดการเคลื่อนไหว (`motion-reduce:hidden`) เพราะเป็นข้อมูล ไม่ใช่ตกแต่ง และปุ่มยังใช้งานได้เหมือนเดิม

| งาน | ไฟล์ | วิธีทำ |
|---|---|---|
| ค่ากลาง motion | ใหม่ `src/client/motion.ts` | ค่า `DUR = { fast: .15, base: .25, slow: .4 }`, `SPRING` (420/26 ที่ใช้ในวงล้อ), `staggerDelay(i, step=.04, max=.4)` ใช้ซ้ำทั้งแอป (มีเทสต์) |
| Aurora ใช้ซ้ำได้ | `AuroraCloud.tsx` | เพิ่ม prop `blur` (ขนาดเล็กใช้ blur น้อย) และโหมด `done` (สงบ เขียว) กับ `error` (เทา นิ่ง) ย้ายค่าของแต่ละโหมดไปเป็นตารางที่ export ได้เพื่อเทสต์ |
| ข้อ 1 AI อ่านรูป | `ScanScreen.tsx`, `Loading.tsx` | แทน `ReadingReceipt` ด้วย `ReadingCloud` (Aurora โหมด thinking + ข้อความ) · แยกขั้นจริงใน mutation: `setStage("resize")` ก่อน `resizeForUpload` → `setStage("ai")` ก่อน `api.parseReceipt` · นับเวลาจริง เกิน 6 วินาทีขึ้นข้อความช้ากว่าปกติ · ลบข้อความที่เปลี่ยนตามเวลาเดิม |
| ข้อ 3 ผลไหลเข้า | `ItemLines.tsx`, `BackfillReview.tsx`, `SayScreen.tsx` | prop `reveal` เปิดเฉพาะครั้งแรกที่ผลจาก AI มาถึง แถวใช้ `motion` + `staggerDelay(i)` · คลาส `flash-once` (CSS keyframe ครั้งเดียว) บนแถว/ช่องที่ `lowConfidence` หรือ `uncertain` |
| ข้อ 10 toast นับเวลา | `Feedback.tsx`, `globals.css` | ถ้า toast มี `action` ใส่แถบในปุ่มที่หดจากเต็มเป็นศูนย์ด้วยเวลาเดียวกับ `t.ms ?? 5000` (ผูก `key` กับ toast id ให้เริ่มใหม่ทุกครั้ง) |
| ข้อ 11 ไฟ streak ติด | ใหม่ `src/client/justLogged.ts`, `useAfterLog.ts`, `StreakWidget.tsx` | store เล็กในหน่วยความจำ (ไม่ใช่ localStorage): `useAfterLog` ตั้ง flag เมื่อ `xpGained >= 10` (เงื่อนไข "จดครั้งแรกของวัน" ที่โค้ดใช้อยู่แล้ว) · `StreakWidget` อ่านแล้วล้าง flag ตอน mount → เล่นจุดวันนี้เด้ง + ไฟพอง + ตัวเลขนับขึ้น (มีเทสต์ของ store) |

### M2 · PR 2 — AI ทุกจุดเป็นชุดเดียว + สวิตช์ (เขียนแล้ว)

ทำบน branch เดียวกับ M1 (ได้สิทธิ์ push เฉพาะ branch นี้) จึงอยู่ใน PR เดียวกับ M1 · ต่างจากแผน: สวิตช์ใช้ `<input role="switch">` มาตรฐาน · `AiBudgetNote` ใช้ `AnimatedNumber` ให้ตัวเลขโควตานับลดเอง (ไม่ต้องมีโค้ดสั่น) · แถบรูปไม่มีรูปย่อ แสดงเลขรูป · หน้าสรุปเดือนแยกบรรทัดจากข้อความด้วยตัวแยกที่มีเทสต์

### ความเสี่ยงรวม
- Aurora (canvas) มีได้ทีละหลายจุดบนหน้าแรก (วิดเจ็ตสรุปเดือน) ต้องวาดเฉพาะตอนมองเห็น (หยุดเมื่อซ่อนแท็บมีแล้ว เพิ่ม IntersectionObserver)
- ข้อ 11, 7, 12, 13 พึ่ง store ในหน่วยความจำ ถ้าผู้ใช้รีเฟรชหน้าระหว่างทาง แค่ไม่เห็น animation ไม่มีผลกับข้อมูล
- ยังไม่มีวิธีทดสอบหน้าตาอัตโนมัติ (หน้าจริงต้อง login + DB) ตรวจด้วยตาจาก Vercel preview ต่อ PR
