# Ubiquitous Language — me-budget

คลังศัพท์กลางของโปรเจกต์ ให้ใช้คำในตารางนี้ให้ตรงกันทั้งในเอกสาร, UI และโค้ด
(คอลัมน์ Code คือชื่อที่ใช้ในโค้ด ถ้าชื่อไหนยังไม่มีในโค้ดหรือโค้ดใช้ชื่ออื่น จะบอกไว้ในหัวข้อ "ชื่อในโค้ดที่ต่างจากตาราง" ท้ายไฟล์)

## ชื่อในโค้ดที่ต่างจากตาราง
- **สตางค์:** ชนิด `Satang` (`number` จำนวนเต็ม) ใน `domain/money.ts` เงินทุกจำนวนในโค้ดและ DB เป็นสตางค์ ส่วน **บาท** ใช้เฉพาะตอนแสดงผล/รับ input (`formatBaht`, `parseBaht`)
- **วัน (เวลาไทย):** ชนิด `DayKey` (`YYYY-MM-DD`) ใน `domain/day.ts`
- **วงล้อ/โหมดการจด:** ใน UI มี `ModeWheel` จริง แต่ `EntryMode` ยังไม่เป็นชนิดในโค้ด หน้าจดรับ query `?mode=expense|income|front` (`front` = ออกก่อนแฟน ไม่ได้ใช้คำว่า `Fronted`)
- **ใบเสร็จ:** ไม่มีชนิด `Receipt` ตัวเดียว ในโค้ดมี `ParsedReceipt` (ที่ AI อ่านออกมา), `ReceiptDraft` (ร่างที่ให้ตรวจ/แก้ ก่อนบันทึก) และรายการที่บันทึกแล้วเป็น `Entry` ที่ `source = "receipt"` พร้อม `ReceiptLine`
- **หาร (`Split`):** ในโค้ดคือ `SplitMode` (`none` | `split` | `partnerAll` | `custom`) สำหรับการออกก่อนแฟน และ `Owner` (`me` | `partner` | `split`) สำหรับบรรทัดใบเสร็จ
- **ปุ่มลัดที่เป็นออกก่อนแฟน:** คอลัมน์ `partnerMode` (`split` | `partnerAll` | ว่าง)
- **ที่มาของรายการ:** `source` = `manual` | `preset` | `receipt` | `wheel` (ตอนนี้หน้าจดส่ง `manual`, ปุ่มลัดส่ง `preset`, ใบเสร็จเป็น `receipt` ส่วน `wheel` ใช้กับรายการแฟนจ่ายคืนเท่านั้น แม้ API จะรับ `wheel` สำหรับรายการปกติได้ก็ตาม)
- **XP:** เก็บเป็นบันทึก `xp_events` (`reason` เช่น `first_log`, `extra_entry`, `partner_cleared`) ไม่มีตัวเลข XP รวมเก็บไว้ ต้องบวกเอา

## ความสัมพันธ์
- **รายจ่าย** 1 รายการมี **ยอดเต็ม** = **ส่วนของเรา** + **ส่วนของแฟน** (ถ้าไม่ได้ **ออกก่อน** ส่วนของแฟนก็เป็น 0)
- **ยอดแฟนติด** = Σ **ส่วนของแฟน** − Σ **แฟนจ่ายคืน** โดยยอดนี้ต้อง ≥ 0 เสมอ (ระบบบันทึกทางเดียว ไม่มีกรณีเราติดแฟน) ดังนั้นแฟนจ่ายคืนได้ไม่เกินยอดแฟนติดที่มีอยู่
- **แฟนจ่ายคืน** ไม่ได้ผูกกับรายการไหน มันหักจาก **ยอดแฟนติด** รวม
- **ใบเสร็จ** 1 ใบ = **รายจ่าย** 1 รายการเสมอ (1 ครั้งที่จ่ายเงิน = 1 รายการ) และมี **บรรทัดใบเสร็จ** ได้หลายบรรทัด
- **ส่วนของเรา**/**ส่วนของแฟน** ของรายการที่มาจากใบเสร็จ = ผลรวมของบรรทัดใบเสร็จตาม **เจ้าของ** (บรรทัดที่เป็น **หาร** จะแบ่งครึ่งเข้าทั้งสองฝั่ง)
- ถ้ารายการมีบรรทัดใบเสร็จ สรุปตาม **หมวด** จะคิดจากหมวดของแต่ละบรรทัด ไม่ได้ใช้หมวดของรายการ
- **บรรทัดใบเสร็จ** แต่ละบรรทัดมี **เจ้าของ** 1 แบบ ทุกครั้งที่เราแก้เจ้าของ ระบบจะอัปเดต **ความจำเจ้าของ** ด้วย
- ลำดับการเดา **เจ้าของ**: **ความจำเจ้าของ** → AI + **โน้ตเกี่ยวกับแฟน** → `เรา` (ติดธง **เดาไม่มั่นใจ**)

## ความกำกวมที่เจอ
- **"วันที่ของรายการ"** (`occurredAt` = วันที่เงินออกจริง) กับ **"เวลาที่กดจด"** (`createdAt`) เป็นคนละอย่าง → สรุปเงินใช้ `occurredAt` ส่วน streak ใช้ `createdAt`
- **"คืนเงิน"** อาจหมายถึงแฟนจ่ายคืนเรา หรือร้านค้า refund ให้เราก็ได้ → ให้ใช้ **แฟนจ่ายคืน** สำหรับกรณีแรกเท่านั้น
- **"รายการ"** เคยใช้ทั้งกับรายการที่เราจดและกับสินค้าในบิล → **รายการ** = Entry และ **บรรทัดใบเสร็จ** = สินค้าในบิล
- **"ครึ่งๆ" / "หาร" / "แชร์"** หมายถึงเรื่องเดียวกัน → ใช้คำว่า **หาร** คำเดียว
- **"ลูกหนี้" / "ยอดค้าง" / "แฟนติด"** หมายถึงเรื่องเดียวกัน → ใช้คำว่า **ยอดแฟนติด** คำเดียว
- **"จด" / "บันทึก"** ใช้แทนกันได้ แต่ใน UI ให้ใช้คำกริยา "จด" เพราะสั้นกว่าและเป็นภาษาที่พี่ใช้เอง
