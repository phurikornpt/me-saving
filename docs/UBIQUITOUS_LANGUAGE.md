# Ubiquitous Language — me-budget

คลังศัพท์กลางของโปรเจกต์ ให้ใช้คำในตารางนี้ให้ตรงกันทั้งในเอกสาร, UI และโค้ด
(คอลัมน์ Code คือชื่อที่ใช้ในโค้ด ถ้าชื่อไหนยังไม่มีในโค้ดหรือโค้ดใช้ชื่ออื่น จะบอกไว้ในหัวข้อ "ชื่อในโค้ดที่ต่างจากตาราง" ท้ายไฟล์)

## ชื่อในโค้ดที่ต่างจากตาราง
- **สตางค์:** ชนิด `Satang` (`number` จำนวนเต็ม) ใน `domain/money.ts` เงินทุกจำนวนในโค้ดและ DB เป็นสตางค์ ส่วน **บาท** ใช้เฉพาะตอนแสดงผล/รับ input (`formatBaht`, `parseBaht`)
- **วัน (เวลาไทย):** ชนิด `DayKey` (`YYYY-MM-DD`) ใน `domain/day.ts`
- **วงล้อ/โหมดการจด:** ใน UI มี `ModeWheel` จริง แต่ `EntryMode` ยังไม่เป็นชนิดในโค้ด หน้าจดรับ query `?mode=expense|income|front` (`front` = ออกก่อน ไม่ได้ใช้คำว่า `Fronted`) หน้ารับเงินคืนรับ `?person=<id>`
- **ใบเสร็จ:** ไม่มีชนิด `Receipt` ตัวเดียว ในโค้ดมี `ParsedReceipt` (ที่ AI อ่านออกมา), `ReceiptDraft` (ร่างที่ให้ตรวจ/แก้ ก่อนบันทึก) และรายการที่บันทึกแล้วเป็น `Entry` ที่ `source = "receipt"` พร้อม `ReceiptLine`
- **หาร:** ในโค้ดคือ `SplitMode` (`none` | `equal` | `theirs` | `custom`) สำหรับรายการที่จดเอง และ `LineOwners` (`{ me: boolean, people: id[] }`) สำหรับบรรทัดใบเสร็จ/รายการย่อย คำนวณใน `domain/split.ts`
- **ยอดติด:** อยู่ใน `domain/ledger.ts` (`Ledger` = `shares` + `repayments` ของทุกคน)
- **ปุ่มลัดที่เป็นออกก่อน:** คอลัมน์ `person_id` + `split_kind` (`equal` | `theirs` | ว่างทั้งคู่ = ของเรา) ปุ่มลัด 1 ปุ่มผูกได้ 1 คน
- **ที่มาของรายการ:** `source` = `manual` | `preset` | `receipt` | `wheel` (ตอนนี้หน้าจดส่ง `manual`, ปุ่มลัดส่ง `preset`, ใบเสร็จเป็น `receipt` ส่วน `wheel` ใช้กับรายการจ่ายคืนเท่านั้น แม้ API จะรับ `wheel` สำหรับรายการปกติได้ก็ตาม)
- **XP:** เก็บเป็นบันทึก `xp_events` (`reason` เช่น `first_log`, `extra_entry`, `balance_cleared` ของเก่าคือ `partner_cleared`) ไม่มีตัวเลข XP รวมเก็บไว้ ต้องบวกเอา

## ความสัมพันธ์
- **รายจ่าย** 1 รายการมี **ยอดเต็ม** = **ส่วนของเรา** + Σ **ส่วนของคน** (ถ้าไม่ได้ **ออกก่อน** ก็ไม่มีส่วนของใคร)
- **ยอดติด** ของแต่ละคน = Σ **ส่วนของคน**นั้น − Σ **จ่ายคืน**ของคนนั้น ต้อง ≥ 0 เสมอ (บันทึกทางเดียว ไม่มีกรณีเราติดใคร) คนหนึ่งจ่ายคืนแทนอีกคนไม่ได้
- **จ่ายคืน** ผูกกับคน แต่ไม่ผูกกับรายการ มันหักจาก **ยอดติด** ของคนนั้นรวมๆ
- **ใบเสร็จ** 1 ใบ = **รายจ่าย** 1 รายการเสมอ (1 ครั้งที่จ่ายเงิน = 1 รายการ) และมี **บรรทัดใบเสร็จ** ได้หลายบรรทัด
- **ส่วนของคน**ในรายการที่มาจากใบเสร็จ = ผลรวมของแต่ละบรรทัดที่มีคนนั้นเป็นเจ้าของ บรรทัดที่มีเจ้าของหลายคนจะหารเท่ากัน (แต่ละคนปัดลง เศษเป็นของเรา)
- ถ้ารายการมีบรรทัดใบเสร็จ สรุปตาม **หมวด** จะคิดจากหมวดของแต่ละบรรทัด ไม่ได้ใช้หมวดของรายการ
- ลำดับการเดา **เจ้าของ** (เฉพาะ**สแกนหารกัน**): **ความจำเจ้าของ** (ตัดเหลือเฉพาะคนที่อยู่ในบิลนี้) → AI + ชื่อและ**โน้ตพฤติกรรม** → `เรา` (ติดธง **เดาไม่มั่นใจ**)
- **ความจำเจ้าของ** อัปเดตตอนบันทึกบิลที่หารกับใครสักคนเท่านั้น และจะไม่ทับความจำที่พูดถึงคนที่ไม่ได้อยู่ในบิลนั้น (นมเปรี้ยว → แฟน จะไม่หายเพราะบิลที่หารกับ A)

## ความกำกวมที่เจอ
- **"วันที่ของรายการ"** (`occurredAt` = วันที่เงินออกจริง) กับ **"เวลาที่กดจด"** (`createdAt`) เป็นคนละอย่าง → สรุปเงินใช้ `occurredAt` ส่วน streak ใช้ `createdAt`
- **"คืนเงิน"** อาจหมายถึงคนอื่นจ่ายคืนเรา หรือร้านค้า refund ให้เราก็ได้ → ให้ใช้ **จ่ายคืน** สำหรับกรณีแรกเท่านั้น
- **"รายการ"** เคยใช้ทั้งกับรายการที่เราจดและกับสินค้าในบิล → **รายการ** = Entry และ **บรรทัดใบเสร็จ** = สินค้าในบิล
- **"ครึ่งๆ" / "หาร" / "แชร์"** หมายถึงเรื่องเดียวกัน → ใช้คำว่า **หาร** คำเดียว
- **"ลูกหนี้" / "ยอดค้าง" / "แฟนติด"** หมายถึงเรื่องเดียวกัน → ใช้คำว่า **ยอดติด** (ของคนนั้น) คำเดียว
- **"แฟน"** เคยเป็นคนเดียวที่ระบบรู้จัก (`partner`) ตอนนี้แฟนเป็นแค่**คน**คนหนึ่ง ข้อมูลเก่าถูกย้ายไปที่คนชื่อ "แฟน" ใน migration `004-people`
- **"จด" / "บันทึก"** ใช้แทนกันได้ แต่ใน UI ให้ใช้คำกริยา "จด" เพราะสั้นกว่าและเป็นภาษาที่พี่ใช้เอง
